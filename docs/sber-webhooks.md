# Уведомления Сбера

2026-10-14. Реализован JSON POST callback по текущему формату Сбера mdOrder/orderNumber/operation/status. Источник: https://ecomtest.sberbank.ru/doc , раздел «Уведомление о проведении платежа [callback]». Код ЮKassa не используется: выбран Сбер.

Публичный путь фронтенда: /api/payments/sber/webhook. Backend: /api/v1/payments/sber/webhook. Уведомления не требуют сессии покупателя или CSRF, поскольку банк не входит в аккаунт. Они только запускают серверную сверку через аутентифицированный getOrderStatusExtended.do; ни status, ни operation из уведомления не выдают доступ. Для существующего платёжного намерения проверяются банковский идентификатор, номер заказа, сумма в копейках и RUB/643. Неизвестные заказы игнорируются без банковского запроса. Максимум 8 КБ JSON; ограничение 8 параллельных сверок на процесс; при недоступности банка 5xx, а не ложный успех.

Ручная кнопка проверки использует тот же код подтверждения. Блокировка строки заказа сериализует повторные/конкурентные уведомления, аудит и изменение доступа фиксируются одной транзакцией до ответа 200. Повторное подтверждение не создаёт второй доступ/аудит. Запоздалое событие перепроверяет актуальное состояние банка. Подтверждение открывает только sandbox_paid; при обнаружении отмены/возврата тестовый доступ закрывается. Подпись callback этим вариантом JSON API не реализована: основание выдачи исключительно ответ аутентифицированного API Сбера. До публичного запуска нужны согласование защиты входящего endpoint с банком и ограничение запросов на прокси.

## Подключение после получения доступа
1. Получить тестовые credentials интернет-эквайринга, сохранить локально на сервере.
2. Настроить публичный HTTPS домен. localhost банк вызвать не сможет.
3. В настройках тестовой учётной записи шлюза указать https://ВАШ-ДОМЕН/api/payments/sber/webhook; если настройка недоступна, обратиться в поддержку/к менеджеру. Согласовать JSON POST уведомления об оплате, отмене и возврате.
4. Установить SBER_SANDBOX_ENABLED=true и SBER_WEBHOOK_ENABLED=true, перезапустить API.
5. В отдельном RELEASE CHECK проверить успешный/отменённый/возвращённый платёж, повторную и параллельную доставку, неверные ID/сумму/валюту, таймаут банка и регистрацию с неопределённым ответом.
