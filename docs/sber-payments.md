# Подготовка эквайринга Сбера

Реальные платежи не подключены. Реализован только адаптер тестовой среды https://ecomtest.sberbank.ru/ecomm/gw/partner/api/v1/ — register.do и getOrderStatusExtended.do. Документация банка: https://ecomtest.sberbank.ru/doc . Поддержка конкретного кабинета и доступность СБП на платёжной форме требуют подтверждения банком. Это не интеграция с обычной личной картой.

## После получения тестового доступа
В backend/.env локально указать SBER_SANDBOX_ENABLED=true, SBER_USERNAME и SBER_PASSWORD — данные тестового эквайринга, не пароль СберБанк Онлайн. Секреты не присылать в чат и не коммитить. Перезапустить API. Назначить положительную цену товару в админке, оформить заказ из каталога; на странице заказа доступны переход к тестовой форме и ручная проверка статуса. Кнопки выключены, пока отсутствуют данные. Реальные credentials сюда не подставлять.

Сервер сохраняет намерение до сетевого запроса и использует неизменный orderNumber. Повторное создание не регистрирует новый платёж. При неопределённом результате доступна проверка по orderNumber; повторная оплата отменённого/неопределённого запроса пока не реализована. Ссылка разрешена только на HTTPS ecomtest.sberbank.ru. Пароль передаётся JSON POST, не в URL. Статус, номер, сумма и валюта проверяются через аутентифицированный запрос к банку. Возврат на сайт не выдаёт доступ. sandbox_paid явно означает тест, а не реальную выручку. Подтверждение и обнаруженная при ручной проверке отмена/возврат записываются в аудит. Учебная выдача не подменяет начатый платёж.

## Перед боевым подключением
Нужны договор эквайринга, активированный СБП, проверенный сценарий чеков и налоговые настройки, публичный HTTPS адрес, callback с серверной перепроверкой, обработка полных/частичных возвратов и повторных попыток, автоматическая сверка незавершённых платежей. Обработчик callback добавлен (см. sber-webhooks.md), внешняя доставка пока не настроена. Фоновая сверка отсутствует. Код намеренно не содержит выбора боевого шлюза.

Проверки не запускались — FAST DEV. Нужны RELEASE CHECK: чужой заказ, CSRF, параллельные нажатия, таймаут после регистрации, несовпадение суммы/валюты/номера, повторное подтверждение, отказ и возврат. Без тестовых credentials связь с банком не проверена. Криптоадаптер не добавлен: провайдер не выбран; для магазина в РФ отдельно требуется определить допустимость такого приёма оплаты.
