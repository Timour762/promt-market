# Подтверждение email и восстановление доступа

## Локальные страницы
- /forgot-password — запрос письма для восстановления.
- /reset-password — форма нового пароля, открывается по ссылке из письма.
- /verify-email — подтверждение адреса, открывается по ссылке из письма.
- /account — повторная подготовка письма для неподтверждённого email.
- /login — ссылка «Не помню пароль».

## Письма
Реальная отправка не подключена. Письма после регистрации, запроса восстановления и повторного подтверждения сохраняются HTML-файлами в C:\Users\timour\Projects\promt-market\.local\mail. Откройте последний файл через Проводник и нажмите ссылку. Отсутствующему аккаунту письмо не создаётся; ответ запроса восстановления одинаковый.

Файлы содержат одноразовые ссылки, это приватная локальная почта. Не публиковать её, не размещать как public/static и не добавлять в Git. Не заменять локальное сохранение реальной отправкой без настройки почтового провайдера и разрешения владельца.

Ссылка подтверждения действует 60 минут, восстановления — 30 минут. Новое письмо того же назначения отменяет предыдущую ссылку. Простое открытие страницы не использует токен: требуется кнопка подтверждения или отправка нового пароля. Письмо может быть создано до открытия страницы; это не доказательство прохождения сценария.

## Backend
Миграция 0003_recovery добавляет auth_tokens и email_outbox. В auth_tokens только SHA-256 токена, назначение, пользователь и срок. Полезная нагрузка ожидающих писем шифруется Fernet; ключ MAIL_ENCRYPTION_KEY хранится в игнорируемом backend/.env. После сохранения HTML полезная нагрузка из outbox удаляется, остаётся статус доставки.

Очередь создаётся в одной транзакции с токеном. После успешного коммита одноразовая background-задача сохраняет до 25 ожидающих писем. Нет таймеров и постоянного опроса. После ошибки сохранения задание остаётся в базе, подробности сообщения не выводятся в журнал. После 5 неудачных попыток требуется ручной разбор причины. Для повторной обработки ожидающих сообщений из backend:

```powershell
.venv\Scripts\python.exe -m app.deliver_mail
```

Ссылки строятся из настроенного PUBLIC_WEB_URL, а не из пользовательского Host. Токен передаётся во фрагменте #token, который не отправляется серверу в URL. Страницы имеют no-referrer и запрет индексации. API использует CSRF и локальное ограничение попыток. Одноразовое использование сериализуется блокировкой пользователя и повторной проверкой токена. После сброса пароля удаляются все сессии пользователя и все оставшиеся auth_tokens, вход автоматически не выполняется.

Реализованы POST /api/v1/auth/resend-verification, /verify-email, /forgot-password, /reset-password. Тексты паролей и токенов исключены из ответов ошибок валидации. Регистрация теперь готовит письмо для подтверждения автоматически.

## Что ещё требуется до production
Почтовый провайдер, HTTPS и production cookie, общие лимиты, ограничения внешних запросов и сценарные проверки. Сейчас доставка только local, поэтому нельзя объявлять подтверждение настоящего почтового адреса проверенным через внешнюю почту.

## SMTP, 2026-10-16
Добавлен MAIL_DELIVERY=smtp с smtp.mail.ru:465 SSL/TLS или явным STARTTLS. Нешифрованного fallback нет. Конфигурация включает SMTP_USERNAME, SMTP_PASSWORD (пароль приложения), SMTP_FROM. До ввода credentials остаётся local. configure_mail.py вводит пароль скрыто, не отправляет письмо. Для будущего сервера mail-worker обрабатывает зашифрованную очередь; не более пяти попыток. SMTP доставка имеет семантику at-least-once: после сбоя между отправкой и фиксацией БД письмо может повториться, стабильный Message-ID помогает идентифицировать его. Последующие ошибки оставляют запись в очереди; фактическая доставка не заявляется без ответа сервера. SMTP-секреты не выводятся в логи. Реальные письма не отправлялись и доставка не проверялась.
