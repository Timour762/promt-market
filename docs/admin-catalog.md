# Административное управление каталогом

## Страницы
- /admin — фактические количества товаров по состояниям, без вымышленных продаж и доходов.
- /admin/prompts — таблица, поиск по названию, фильтр состояния, страницы по 50 записей.
- /admin/prompts/new — создание черновика.
- /admin/prompts/{id} — редактор товара.
- /admin/audit — журнал действий с товарами.

Ссылка «Управление» доступна администратору в шапке и личном кабинете. Для обычного пользователя страницы направляют в личный кабинет; каждый backend endpoint независимо требует активную серверную сессию и роль admin.

## Редактор
Отдельная страница формы, без модального окна. Раздел 1: публичная карточка, категория, цена в рублях, описание и результат. Раздел 2: закрытый текст, по раскрытию. Раздел 3: адрес и обозначение обложки, по раскрытию. Главная кнопка сохраняет; действия видимости находятся в отдельной сводке и недоступны при несохранённых правках.

Адрес задаётся при создании и не меняется. Используются существующие категории; управление справочниками и загрузка изображений ещё не добавлены. Цена хранится целым числом копеек; пустое поле означает неназначенную цену. Десятичная строка преобразуется без вычислений с дробными денежными значениями. Цена 0 допустима, но покупки, включая бесплатную выдачу, пока не подключены.

## Состояния
- draft — скрыт из публичного API и витрины.
- published — карточка видна; полный текст остаётся закрытым.
- archived — скрыт; товар и версии текста не удаляются.

Новый товар всегда создаётся черновиком. Публикация требует сохранённой цены и непустого текста. Для опубликованного товара нельзя сохранить пустой текст или убрать цену: сначала перевести в черновик. Начальные шесть товаров раньше были опубликованы без цены; при редактировании нужно назначить цену либо сначала перевести их в черновик. Оплата не подключена, публикация означает только видимость в локальном каталоге.

## Сохранение и история
Изменение полного текста создаёт новую prompt_versions. Старые версии сохраняются. Ревизия записи увеличивается при сохранении и смене состояния; клиент передаёт ожидаемую ревизию. Под блокировкой строки несовпадение возвращает 409, не перезаписывая чужую правку. При конфликте скопировать изменения и обновить страницу.

Миграция 0005_admin_catalog добавляет prompts.revision и audit_logs. Журнал содержит автора, тип действия, товар, ревизию и безопасные метаданные. Полные тексты, пароли и cookie в него не попадают. Изменение товара и запись аудита выполняются одной транзакцией. Физического удаления товара нет.

## Защита
GET /api/v1/admin/dashboard, /categories, /prompts, /prompts/{id}, /audit требуют admin. POST /prompts, PATCH /prompts/{id}, POST /prompts/{id}/publish, /archive, /draft дополнительно требуют CSRF и разрешённый Origin. Административные ответы no-store. Закрытый текст отдаётся только в защищённом редакторе администратора; публичные схемы остались без него.

## Текущий статус
Миграция применена к локальной базе, FastAPI перезапущен. Тесты, API/браузерные сценарии и build не запускались — FAST DEV. Агент не менял цены, тексты и состояния товаров для демонстрации. Коммит, push и публикация в интернет не выполнялись.

Перед production проверить запрет доступа customer/гостя, CSRF, конкурентные правки, версионирование текста, цены, публикацию/архив и отсутствие защищённого текста в публичных ответах. До подключения оплаты необходим отдельный этап заказов и прав доступа.
