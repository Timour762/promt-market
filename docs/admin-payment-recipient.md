# Реквизиты карты в кабинете администратора

С 2026-10-19 вместо формы карты в кабинете показывается настройка [Platega](platega.md). Сохранённые данные старого сценария не удалены.

2026-10-18. Форма /account появляется только при role=admin. Timour использует существующую роль admin; проверка не основана на отображаемом имени. API GET/PATCH /api/v1/admin/payment-details требует действующую сессию admin, PATCH дополнительно CSRF. Frontend-прокси разрешает только этот PATCH и не предоставляет обычным пользователям доступ: роль проверяется backend.

Миграция 0008 добавляет единственную запись payment_recipient для магазина. Номер проверяется по длине/цифрам и Luhn, шифруется Fernet отдельным PAYMENT_DETAILS_ENCRYPTION_KEY. В ответы GET/PATCH возвращается только маска с последними четырьмя цифрами. Для смены нужно ввести номер заново; пустой ввод сохраняет существующую карту. От имени получателя и банка нельзя автоматически определить настоящего владельца карты. Изменения защищены revision/409, pg_advisory_xact_lock сериализует первичное создание. Аудит хранит только факт смены и revision, без реквизитов.

Ключ создаётся только в закрытой локальной backend/.env и не коммитится. При размещении нужно сохранить ключ отдельно вместе с зашифрованной резервной копией БД. Эта настройка не включает приём переводов и не подтверждает поступление денег; рабочий покупательский сценарий ручной оплаты остаётся отдельным незавершённым этапом.

Проверки не запускались — FAST DEV. Перед публикацией требуются проверки роли, CSRF, скрытия PAN, конкурирующих правок и шифрования. Реальные номера агент не вводил и не менял.
