# Оплата переводом с подтверждением администратора

С 2026-10-19 для новых оплат используется [Platega](platega.md). Эта инструкция описывает сохранённый сценарий старых ручных заказов.

Покупатель оформляет заказ и нажимает «Оплатить». Открывается `/account/orders/<id>/payment` с суммой заказа, именем получателя, банком и номером карты. Реквизиты берутся из настроек администратора в `/account`; при отсутствии реквизитов заказ остаётся неоплаченным и выводится объяснение.

Нажатие «Оплатить» переводит заказ в `awaiting_confirmation` и добавляет его в список «Ожидают подтверждения» в личном кабинете администратора. Это заявка на проверку: переход на страницу сам по себе не подтверждает поступление денег. Администратор сверяет перевод в своём банке и нажимает «Подтвердить» в строке покупателя. Заказ становится `paid`, открывается сохранённая версия промпта в библиотеке. Подтверждать заказ можно только с ролью администратора и действующим CSRF-токеном.

Страница покупателя проверяет статус каждые 5 секунд, список администратора — каждые 7 секунд. Ожидание сохраняется после обновления страницы и перезапуска API. Повторное нажатие и одновременное подтверждение не дублируют оплату или запись журнала. Цена берётся из заказа, реквизиты сохраняются в отдельном зашифрованном снимке; смена карты или цены товара не меняет уже начатую оплату. В списке администратора показываются только последние четыре цифры карты. Полные реквизиты доступны только владельцу ожидающего заказа.

Миграция: `.venv/Scripts/python.exe -m alembic upgrade head` из `backend`. Для расшифровки используется существующий `PAYMENT_DETAILS_ENCRYPTION_KEY`; его нужно сохранять вместе с резервной копией базы.

Проверки: из `backend` — `.venv/Scripts/python.exe -m unittest tests.test_security -v`; из `frontend` — `npm run typecheck`, `npm run test:payments`, `npm run build`. Браузерные проверки запускают отдельные API (8117) и сайт (3117), временную схему PostgreSQL и вымышленные реквизиты. Они не изменяют пользователей, заказы или карту рабочего локального магазина. Если принудительное завершение браузерных серверов не вызвало очистку временной схемы, из `backend` запустить `.venv/Scripts/python.exe -m tests.manual_payment_server --cleanup` после остановки тестов.
