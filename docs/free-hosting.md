# Бесплатное размещение: состояние подготовки

Владелец хочет постоянный публичный адрес, пока без аккаунта облачного сервиса и подходящей карты. Бюджет — 0 ₽. Пользователь согласился на пробуждение после простоя. Выбранное направление подготовки — Render Free для приложения и Neon Free для PostgreSQL. Облачные ресурсы не созданы, данные и секреты никуда не загружены.

## Доступные направления

- Для демонстрации можно рассмотреть бесплатный Render и отдельную базу Neon. У Render есть сон после 15 минут простоя, пробуждение занимает около минуты. Лимиты бесплатных часов, трафика и сборок действуют независимо от постоянства ссылки. Сам Render не рекомендует Free для production.
- Бесплатный Render Postgres не подходит как бессрочная база: он истекает через 30 дней. У Neon есть отдельный Free-план с собственными квотами; перед созданием следует проверить условия регистрации и доступность сервиса для пользователя.
- Для режима без задержек 24/7 нужен подходящий постоянно работающий сервер. Бесплатный VPS без карты с гарантированной доступностью для данного пользователя не подтверждён. Временный пробный грант нельзя выдавать за бессрочный бесплатный сервер.

## Совместимость текущего проекта

Текущий `deploy/compose.yaml` рассчитан на VPS с Docker Compose: PostgreSQL, миграции, API, mail-worker, Next.js и Caddy. В Render этот Compose-файл напрямую не запускается. Для его бесплатного тарифа потребуется отдельная схема размещения приложения и внешней базы; два постоянно включённых сервиса расходовали бы общий лимит бесплатных часов.

Бесплатный Render блокирует исходящий SMTP на портах 25/465/587. В проекте сейчас используется SMTP Mail.ru, а production-режим требует настроенную почту. Для такого размещения сначала нужно согласовать и реализовать совместимую отправку писем, например через HTTPS API выбранного почтового сервиса. Нельзя обходить проверку production установкой локального режима или помечать незавершённые документы готовыми ради старта.

Docker локально недоступен, поэтому сборка контейнеров не проверена. Структура Compose прочитана YAML-парсером: шесть сервисов, наружу опубликованы только 80/443. В инструкции исправлена загрузка `deploy/.env` через `--env-file`; в серверный шаблон добавлены отключённые настройки Platega.

Следующий шаг: владелец регистрируется в Render (https://dashboard.render.com/register) и Neon (https://console.neon.tech/signup), выбирая только Free. Репозиторий проекта уже имеет origin https://github.com/Timour762/promt-market.git; наличие remote не подтверждает, что текущие локальные изменения опубликованы. Затем подготовить схему запуска под Render и совместимую отправку почты, проверить их и подключать публичный HTTPS-адрес. Не запускать текущий Compose напрямую на Render. Секреты хранятся в закрытой конфигурации, не в чате или репозитории.
