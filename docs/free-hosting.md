# Бесплатное размещение: состояние подготовки

Владелец хочет постоянный публичный адрес без подходящей карты. Бюджет — 0 ₽. Пользователь согласился на пробуждение после простоя. Выбраны Render Free для приложения и Neon Free для будущей PostgreSQL. Проект Neon создан. В форме Render импортированы переменные и выбран тариф $0. Первая публикация по выбору владельца — витрина без регистрации и оплаты (`PUBLIC_PREVIEW=true`), полный магазин позже. Публичный HTTPS пока не проверен.

Витрина запускает только Next.js с публичными описаниями шести промптов. Backend, база, миграции и почтовый worker не запускаются; неизвестная доступность Neon не блокирует показ сайта. Вход, кабинет, закрытые тексты, заказы, платежи и все изменяющие запросы недоступны. `LEGAL_READY=false` сохранён, документы будущих продаж остаются черновиками. Подробные поля формы и дальнейший переход к полному магазину — в [инструкции Render](render.md).

## Текущее подключение Neon

Пользователь создал проект Neon и сохранил прямую строку подключения в игнорируемом `.local/neon.env`. Формат строки проверен без вывода реквизитов. Проверки с этого компьютера разрешили DNS и обнаружили частичную доступность TCP 5432, однако PostgreSQL-соединение завершилось таймаутом, в том числе при приоритетном выборе доступных адресов с сохранением проверки TLS и SNI. Работоспособность учётных данных и SQL-запросы пока не подтверждены. Схема, каталог и пользователи в Neon не переносились. Локальный `backend/.env` не менялся. Следующий этап — подготовка сервиса Render и проверка соединения из его окружения.

## Доступные направления

- Для демонстрации можно рассмотреть бесплатный Render и отдельную базу Neon. У Render есть сон после 15 минут простоя, пробуждение занимает около минуты. Лимиты бесплатных часов, трафика и сборок действуют независимо от постоянства ссылки. Сам Render не рекомендует Free для production.
- Бесплатный Render Postgres не подходит как бессрочная база: он истекает через 30 дней. У Neon есть отдельный Free-план с собственными квотами; перед созданием следует проверить условия регистрации и доступность сервиса для пользователя.
- Для режима без задержек 24/7 нужен подходящий постоянно работающий сервер. Бесплатный VPS без карты с гарантированной доступностью для данного пользователя не подтверждён. Временный пробный грант нельзя выдавать за бессрочный бесплатный сервер.

## Совместимость текущего проекта

Текущий `deploy/compose.yaml` рассчитан на VPS с Docker Compose: PostgreSQL, миграции, API, mail-worker, Next.js и Caddy. В Render этот Compose-файл напрямую не запускается. Подготовлена отдельная схема: `deploy/render/Dockerfile` запускает web, API и mail-worker в одном сервисе с внешней базой Neon. Подробные настройки формы и оставшиеся шаги приведены в [инструкции Render](render.md). Актуальное приложение и подготовка находятся в ветке `codex/database-catalog`; `main` содержит старую версию. Публичный сервис ещё не запущен.

Бесплатный Render блокирует исходящий SMTP на портах 25/465/587. Владелец создал кабинет Brevo, но сообщил, что подтверждение российского номера не поддерживается и ключ получить не удалось. После подтверждения наличия Gmail подготовлена замена: Google Apps Script с подписанными HTTPS-запросами, без отдельного домена отправителя. Владелец уже разместил скрипт: реальная подписанная проверка прошла и вернула квоту 100 получателей, URL сохранён только в частной конфигурации. Письма не отправлялись; [пошаговая инструкция](google-mail.md). Пользователь подтвердил, что документы ещё являются шаблонами, поэтому `LEGAL_READY=false` сохранён. Нельзя обходить проверку production установкой локального режима или помечать незавершённые документы готовыми ради старта.

Docker локально недоступен, поэтому сборка контейнеров не проверена. Структура Compose прочитана YAML-парсером: шесть сервисов, наружу опубликованы только 80/443. В инструкции исправлена загрузка `deploy/.env` через `--env-file`; в серверный шаблон добавлены отключённые настройки Platega.

Владелец уже зарегистрировался в Render и Neon, открыл форму Web Service, выбрал Free и импортировал частную конфигурацию. Подготовка контейнера и Google mail опубликована в `codex/database-catalog`. Следующий шаг первой витрины — после публикации её изменений добавить `PUBLIC_PREVIEW=true`, проверить Dockerfile и ветку и нажать Deploy. Полные документы и доступ к Neon требуются для последующего открытия магазина. Google mail уже отвечает на подписанную проверку. Репозиторий проекта имеет origin https://github.com/Timour762/promt-market.git. Не запускать текущий Compose напрямую на Render. Секреты хранятся в закрытой конфигурации, не в чате или репозитории.
